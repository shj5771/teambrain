# 팀원 각자의 AI를, 팀 하나의 AI처럼 만들기

> TeamBrain을 만들며 고민한 것들. 블로그나 발표의 원고로 쓸 수 있게 정리한 글입니다.

## 조사는 몇 시간, 합의는 몇 주

우리 팀은 셋이서 프로젝트 주제를 정하는 데만 몇 주가 걸렸다. 아이디어가 없어서가 아니었다.
각자 AI로 조사해서 꽤 그럴듯한 결론에 금방 도달했는데, 그 결론을 서로에게 납득시키는 데 시간이 걸렸다.

이유는 단순했다. 결론에 이르는 맥락(무엇을 찾아봤는지, 왜 다른 대안은 아닌지)은 각자의 AI 채팅창에만 남았다.
팀에는 결론만 말로 전달됐다. 근거가 전달되지 않으니 공감을 얻지 못했고, 같은 논의가 반복됐다.

AI 덕분에 개인은 빨라졌다. 그런데 팀은 그대로였다. 병목이 "정보 부족"에서 "사람 사이의 합의"로 옮겨간 것이다.

팀원마다 AI 봇을 쓰면, AI도 사람 수만큼 따로 논다. 지민의 봇이 들은 결정을 서준의 봇은 모른다.

## 만들지 않기로 한 것들

처음 그린 그림은 거창했다. 메신저, 개인 AI, 지식 그래프, 권한 시스템까지 다 있었다.
그런데 메신저(Mattermost)와 개인 AI 에이전트(Hermes)는 이미 훌륭한 오픈소스가 있었다. 게다가 둘은 이미 서로 연결돼 있었다.

그래서 우리가 만드는 것은 그 사이의 얇은 층 하나, **팀 기억**으로 정했다. ([결정 0001](decisions/0001-connect-dont-rebuild.md))

연결 방법은 다섯 가지를 같은 기준으로 비교했다. 그중 에이전트의 공식 메모리 플러그인 인터페이스를 골랐다.
에이전트 코드를 한 줄도 고치지 않고, 매 대화의 전후에 끼어들 수 있었다. ([결정 0002](decisions/0002-integration-point.md))

라이선스도 설계의 일부였다. 메신저 서버는 AGPL이라 수정하면 소스 공개 의무가 생긴다.
그래서 메신저는 순정 그대로 두고 공개 API로만 통신하고, 우리 코드는 항상 별도 프로세스에 두었다. ([결정 0003](decisions/0003-license-boundary.md))

## 가장 크게 뒤집힌 것: 프라이버시

기획 초기에 프라이버시는 "보조 기능"이었다. 팀 공유가 주인공이었다.

그런데 사용자 인터뷰에서 이런 말을 들었다. "내가 이런 기초적인 것까지 물어봤다는 걸 동료가 알까 봐 쓰기 싫다."

팀 기억이 개인 대화를 한 번이라도 흘리면 사람들은 봇에게 아무것도 묻지 않을 것이고, 그러면 팀 기억도 쌓이지 않는다.
프라이버시는 보조 기능이 아니라 **제품이 성립하기 위한 전제**였다.

그래서 규칙을 최대한 단순하고 검증 가능하게 만들었다.

- 완전 공개 채널에서 한 대화만 기록한다.
- DM, 비공개 채널은 기록하지 않는다. **판단할 수 없으면 기록하지 않는다.**
- "DM 내용이 위키 정리 프롬프트에 절대 들어가지 않는다"를 테스트로 고정했다.

([결정 0005](decisions/0005-privacy-fail-closed.md))

## 지식 체계를 설계하지 않기로 한 이유

팀 기억을 어떤 구조로 쌓을지에 대해 초안이 네 개나 나왔다. 결정·사실·할 일·노하우로 분류하자는 안도 있었고, 벡터 DB에 넣자는 안도 있었다.

한 멘토가 찬물을 끼얹었다. "AI로 지식 체계를 자동 구축하려는 시도는 대부분 실패했다. 조직마다 지식의 모양이 다르다."

맞는 말이었다. 그래서 정답 체계를 미리 설계하는 대신 두 층으로 나눴다.

1. **원본**: 공개 채널 대화를 해석 없이 그대로 기록한다.
2. **위키**: 대화가 쌓이면 AI가 주제별 Markdown 문서로 정리한다.
   - 모든 사실에 누가·어디서·언제를 붙인다.
   - 결정이 바뀌면 덮어쓰지 않고 변경 이력으로 남긴다.

AI가 틀려도 출처를 따라가면 확인할 수 있다. 정리 방식이 마음에 안 들면 원본에서 다시 만들면 된다.
([결정 0006](decisions/0006-raw-log-plus-llm-wiki.md))

## 결과

```
#dev 채널    지민 → @지민봇  "DB는 Postgres로 가자. JSON 컬럼이랑 전문검색이 필요해서"
일주일 뒤     서준 → @서준봇  "우리 DB 뭐 쓰기로 했지?"
              @서준봇        "지민님이 #dev에서 정했어요: PostgreSQL. JSON 컬럼과 전문 검색이 필요해서요."
```

같은 기억은 편집기 안의 AI(Claude Code, Cursor 등)에서도 MCP로 꺼내 쓸 수 있다. ([결정 0007](decisions/0007-mcp-read-only.md))

## 데모를 찍다가 배운 것

실제 메신저와 실제 AI 모델로 데모를 찍으면서 테스트에서는 안 보이던 문제들을 찾았다.

- **봇이 내 컴퓨터에 파일을 썼다.** "팀 위키에 정리해줘"라는 말에, 에이전트가 우리 위키 도구 대신 자기 파일 쓰기 도구를 썼다.
  팀 채널에 붙는 봇에게는 파일·터미널 도구를 주지 말아야 한다는 걸 배웠다.
- **위키 출처에 채널 이름이 "#channel"로 찍혔다.** 에이전트는 채널 ID만 넘겨줬다. 그래서 메신저 API로 이름을 조회하도록 고쳤다.
- **질문한 사람이 결정한 사람으로 기록됐다.** "DB 뭐 쓰기로 했지?"라고 물은 서준이 출처가 됐다. 그래서 질문은 출처로 쓰지 않는다는 규칙을 정리 프롬프트에 넣었다.
