# 0001. 메신저도 AI 에이전트도 새로 만들지 않는다

- 상태: 채택

## 상황

풀고 싶은 문제는 "팀원 각자가 AI로 알아낸 것과 팀이 내린 결정이 개인 채팅창에 갇혀, 팀이 같은 질문과 논쟁을 반복한다"는 것이었다.
이를 해결하는 제품에는 세 부분이 필요하다.

1. 팀원이 매일 쓰는 **메신저**
2. 팀원 각자를 기억하고 학습하는 **개인 AI 에이전트**
3. 개인 AI들이 들은 것을 팀의 기억으로 모으는 **연결 층**

1번과 2번은 이미 성숙한 오픈소스가 있다. 자체 호스팅 메신저로는 Mattermost가 있고, 세션을 넘어 사용자를 학습하는 개인 에이전트로는 Hermes Agent가 있다.
특히 Hermes에는 Mattermost 연결 기능이 이미 들어 있었다. 인증, 재연결, 멘션 판별, 스레드 처리까지 약 1,300줄 분량이다.
이 사실은 소스 코드 확인, 공식 API 문서 대조, 로컬 실행 세 가지로 확인했다.

## 결정

1번과 2번은 손대지 않고 그대로 쓴다. **우리가 만드는 것은 3번, 팀 기억 층뿐**이다.

## 결과

- 얻은 것: 작은 팀이 제품의 진짜 새로운 부분에만 집중할 수 있다. 메신저 앱(모바일·데스크톱)과 에이전트 기능은 각 프로젝트가 계속 발전시킨다.
- 감수한 것: 두 프로젝트의 변경에 영향을 받는다. 그래서 연결 지점은 비공식 내부 코드가 아니라 **공식 확장 지점**으로 골랐다. ([0002](0002-integration-point.md))
- 처음 기획서에는 "메신저 → 우리 어댑터 → 에이전트"라는 그림이 있었다. 코드를 직접 확인한 뒤, 근거 없이 그린 그림이었다는 걸 알고 바로잡았다.
