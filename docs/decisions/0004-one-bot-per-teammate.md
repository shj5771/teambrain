# 0004. 팀원마다 봇을 하나씩 둔다

- 상태: 채택

## 상황

목표는 "팀원 각자에게 그 사람을 학습하는 AI가 붙고, 그 AI들이 팀 기억을 공유하는 것"이었다.
처음에는 `@ai` 봇 하나를 팀 전체가 같이 쓰는 것이 가장 단순해 보였다.

코드를 확인해 보니 에이전트의 "분리"에는 두 단계가 있었다.

- **1단계, 대화 기록 분리**: 봇 하나로도 발신자별로 대화 기록은 자동으로 나뉜다.
- **2단계, 프로필 분리**: AI의 성격(`SOUL.md`), 사용자에 대해 학습한 내용(`USER.md`), 스킬, 설정은 **프로필 단위로만** 존재한다.
  봇 하나를 같이 쓰면 팀 전원이 한 프로필을 공유하게 된다. "서준에 대해 배운 것"과 "지민에 대해 배운 것"이 한 파일에 섞인다.

즉 봇 하나로는 "나를 학습하는 AI"를 만들 수 없었다.

## 검토한 선택지

| 방법 | 결과 |
|---|---|
| A. 팀원별 봇 계정 + 에이전트 프로필 | 공식 기능만으로 가능. 프로세스 하나가 여러 프로필을 함께 서비스 |
| B. 봇 하나 + 발신자를 감지하는 자체 코드 | 가능하지만 비공식 확장이라 업스트림이 바뀌면 깨질 위험 |
| C. 외부 API 창구에서 주소로 사람 구분 | **불가능**(해당 창구에는 사람별 라우팅 기능이 없음을 코드로 확인) |
| D. 팀원 수만큼 에이전트를 통째로 복제 | 가능하지만 팀이 커질수록 운영 부담도 커짐 |

## 결정

**A안.** 팀원마다 봇 계정과 프로필을 하나씩 두고, 각 봇은 허용 목록으로 "주인만 부를 수 있게" 제한한다.
팀 기억은 모든 프로필이 같은 메모리 플러그인을 쓰는 방식으로 공유한다.

## 결과

- 얻은 것: 개인화는 에이전트의 공식 기능에 맡기고, 우리는 팀 공유에만 집중한다. 실제 메신저에서 프로필별로 학습 내용이 분리되는 것을 확인했다.
- 감수한 것: 팀원은 "자기 봇"의 이름을 알아야 하고, 팀원이 늘 때마다 봇 계정을 새로 만들어야 한다. 이 과정은 자동화 대상이다.
